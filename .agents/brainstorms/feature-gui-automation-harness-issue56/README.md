## 🎯 **BRAINSTORM PROCESS**

### Phase 1: Proposals (CURRENT)

```yaml
Goal: Each AA drafts independent proposal

Timeline: Ongoing (async)
  - Cursor: ✅ Complete (2025-10-28)
  - Codex: Next session
  - Gemini: Future session

Instructions:
  1. Read topic description (in your file)
  2. Draft YOUR proposal (your file)
  3. Don't look at others yet (stay independent)
  4. Commit when done
  
Output: 3 files per topic (cursor/codex/gemini-proposal.md)
Status: 33% complete (Cursor done)
```

### Phase 2: Discussion (After all proposals)

```yaml
Goal: Understand each other's perspectives

Process:
  1. Read ALL proposals for a topic
  2. Add comments to discussion.md
  3. Ask clarifying questions
  4. Challenge assumptions (constructive)
  5. Identify common ground
  
Format in discussion.md:
  ## [YOUR_NAME]'s Comments (Date)
  
  ### On Cursor's Proposal
  [Your thoughts]
  
  ### On Codex's Proposal
  [Your thoughts]
  
  ### On Gemini's Proposal
  [Your thoughts]

Output: discussion.md with all AA comments
```

### Phase 3: Consensus Building

```yaml
Goal: Agree on approach to TEST

Process:
  1. Review discussion
  2. Identify common ground
  3. Propose specific approach (for testing)
  4. Vote/sign-off
  
Consensus Criteria:
  - ≥2 AAs agree: PASS (move to testing)
  - <2 AAs agree: Continue discussion OR User decides

Output: consensus.md with:
  - Agreed approach (specific)
  - Test plan (measurable)
  - Success criteria (clear)
  - Sign-offs (who agreed)
```

### Phase 4-6: Testing → Adoption

```yaml
Test: Implement agreed approach
Measure: Collect evidence
Validate: Pass/fail determination
IF Proven: Update lessons/principles
IF Failed: Iterate (refine and re-test)

Location: Normal git workflow (not brainstorm folder)
```

## 🎓 **IMPORTANT PRINCIPLES**

### Remember Always

```yaml
✅ Proposals = Hypotheses (not conclusions)
✅ Consensus = Agreement to test (not final truth)
✅ Testing = Required (no skipping!)
✅ Only proven → Lessons (quality gate)

❌ Don't claim consensus as fact (still hypothesis)
❌ Don't skip testing (must validate)
❌ Don't update lessons before proof (premature)
❌ Don't force agreement (OK to disagree, test both)

Process: Hypothesis → Consensus → Test → Proven → Lesson
```

### Why Separate Files?

```yaml
Reality:
  - User works with 1 AA at a time (sequential)
  - IDE CLI (local files in .agents/)
  - .agents/ = SSoT (git-ignored)

Solution:
  - Each AA = own file (no conflicts)
  - No locks needed (sequential by nature)
  - Git commits track evolution
  - Local-first (CLI friendly)

Result:
  ✅ No merge conflicts (separate files)
  ✅ Clear attribution (file names)
  ✅ Fast local access (IDE reads)
  ✅ Version control (git history)
```
